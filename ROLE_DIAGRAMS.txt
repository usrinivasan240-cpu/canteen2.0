# SECTION 10: CACHED DATA FLOW (Page Load Optimization)
# ============================================================

  ┌─────────────────────────────────────────────────────────┐
  │               FIRST PAGE LOAD                            │
  │                                                         │
  │  1. App.tsx initializes from localStorage:              │
  │     bb_user ──► currentUser (instant)                   │
  │     bb_role ──► role (instant)                          │
  │     bb_loggedIn ──► isLoggedIn (instant)                │
  │                                                         │
  │  2. Page renders IMMEDIATELY from cached data           │
  │     (no blank screen, no loading spinner)               │
  │                                                         │
  │  3. Background refresh fires:                           │
  │     fetchCanteenData() ──► GET /api/canteen             │
  │     fetchUserOrders() ──► GET /api/user/orders          │
  │     fetchColleges() ──► GET /api/colleges               │
  │                                                         │
  │  4. Fresh data overwrites cache:                        │
  │     localStorage.setItem('bb_canteen', freshData)       │
  │     localStorage.setItem('bb_orders', freshOrders)      │
  │     localStorage.setItem('bb_colleges', freshColleges)  │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │               SUBSEQUENT PAGE LOADS                      │
  │                                                         │
  │  1. App renders instantly from localStorage             │
  │  2. Background fetch updates data silently              │
  │  3. UI updates when fresh data arrives                  │
  │  4. User perceives INSTANT load time                   │
  └─────────────────────────────────────────────────────────┘

  Cache Keys:
    bb_user        → Current user object
    bb_role        → User role string
    bb_loggedIn    → "true" flag
    bb_canteen     → Canteen data (items, orders, reviews, ingredients)
    bb_orders      → User's personal orders
    bb_colleges    → Colleges list
    bb_canteens    → Canteens list
    bb_subcanteens → Subcanteens list

# SECTION 15: SUMMARY - HOW ALL PIECES CONNECT
# ============================================================

  ┌─────────────────────────────────────────────────────────┐
  │                                                         │
  │  1. SUPERADMIN creates colleges and canteens            │
  │                                                         │
  │  2. SUPERADMIN assigns OWNER to each canteen            │
  │     (sets ownerId on canteen document)                   │
  │                                                         │
  │  3. OWNER creates menu items, ingredients               │
  │     Items are linked to canteenId                       │
  │                                                         │
  │  4. CUSTOMER signs up with email + OTP                  │
  │     Auto-assigned to their college's canteen            │
  │     (first active canteen matching their collegeId)     │
  │                                                         │
  │  5. CUSTOMER browses menu, places order                 │
  │     Order linked to userId + canteenId + collegeId      │
  │                                                         │
  │  6. PAYMENT: Paytm processes, server verifies           │
  │     Order status: pending → paid                        │
  │                                                         │
  │  7. CHEF sees order on board, marks "preparing"         │
  │     Then marks "ready" when done                        │
  │                                                         │
  │  8. STAFF sees "ready" order, scans QR, marks           │
  │     "collected"                                         │
  │                                                         │
  │  9. CUSTOMER sees status updates in real-time           │
  │     Views QR code in order history                      │
  │                                                         │
  │  10. CUSTOMER submits review → linked to canteen        │
  │      AI analyzes sentiment                              │
  │                                                         │
  │  11. SUPERADMIN monitors everything via dashboard       │
  │      Can override, reset, manage any entity             │
  │                                                         │
  │  12. On page refresh: localStorage restores session     │
  │      Orders fetched for logged-in user only             │
  │      UI renders instantly from cache                    │
  │                                                         │
  └─────────────────────────────────────────────────────────┘
